# 06 · 服务器部署流程、踩坑记录

> **先说明验证范围**：本项目的接口是在 Windows 本机（Java 26 + MySQL 5.7.29）实测通过的。
> 下面第 1～7 节是**通用 Linux 服务器部署流程**，我没有云服务器，属于按官方文档整理的步骤，尚未逐条实测；
> 第 8 节的踩坑，✅ 标记的是我在这个项目里**真实遇到并解决**的，其余是同类项目的高频坑，提前写下来防身。

---

## 1. 服务器准备

以 Ubuntu 22.04 / 2 核 2G 为例。

| 项目 | 建议 |
|---|---|
| 系统 | Ubuntu 22.04 LTS |
| 配置 | 2C2G 起步（JVM + MySQL 同机够学习用） |
| 安全组 | 放行 22（SSH）、80 / 443（HTTP/HTTPS）；**不要**对公网开放 3306 和 8080 |

登录服务器：

```bash
ssh root@你的服务器IP
```

先更新系统：

```bash
apt update && apt upgrade -y
```

---

## 2. 安装 JDK 17

```bash
apt install -y openjdk-17-jdk
java -version
```

> 项目 `pom.xml` 里编译目标是 17，装 17 或 21 都可以。
> 如果服务器已装多个 JDK，用 `update-alternatives --config java` 选择。

---

## 3. 安装 MySQL 并初始化数据

```bash
apt install -y mysql-server
systemctl enable --now mysql
mysql_secure_installation   # 按提示设置 root 密码、删匿名用户
```

建库建表：把项目里的 `sql/` 目录传上去，然后执行。

```bash
scp -r sql root@你的服务器IP:/opt/task-api/
```

```bash
mysql -u root -p < /opt/task-api/sql/01_create_database.sql
mysql -u root -p task_manager < /opt/task-api/sql/02_create_table.sql
```

> `01_create_database.sql` 建的是 `task_app@localhost` 和 `task_app@127.0.0.1`。
> 如果应用和数据库不在同一台机器，要额外建 `task_app@'应用服务器IP'` 并授权。

验证：

```bash
mysql -u task_app -p task_manager -e "SHOW TABLES; DESC task;"
```

---

## 4. 本地打包，上传 jar

在**本地**项目根目录：

```bash
./mvnw clean package -DskipTests
```

生成 `target/task-manager-1.0.0.jar`，上传：

```bash
scp target/task-manager-1.0.0.jar root@你的服务器IP:/opt/task-api/
```

服务器上先手动试跑一次：

```bash
cd /opt/task-api
java -jar task-manager-1.0.0.jar
```

另开一个终端验证：

```bash
curl http://127.0.0.1:8080/api/tasks
```

返回 `[]` 或数组就说明能跑。

> 生产环境不要把数据库密码写在配置文件里。用环境变量注入（见下一节）。

---

## 5. 用 systemd 托管（开机自启、崩溃重启）

创建服务文件：

```bash
nano /etc/systemd/system/task-api.service
```

内容：

```ini
[Unit]
Description=Task Manager API
After=network.target mysql.service

[Service]
Type=simple
User=www-data
WorkingDirectory=/opt/task-api

# 数据库配置通过环境变量注入，不写进 jar
Environment="DB_URL=jdbc:mysql://127.0.0.1:3306/task_manager?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true"
Environment="DB_USERNAME=task_app"
Environment="DB_PASSWORD=换成你的强密码"
Environment="SERVER_PORT=8080"

ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/task-api/task-manager-1.0.0.jar
SuccessExitStatus=143

Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
systemctl daemon-reload
systemctl enable --now task-api
systemctl status task-api
```

看日志：

```bash
journalctl -u task-api -f
```

**注意**：`ExecStart` 里的 `java` 要写绝对路径。systemd 不读你 shell 的 `PATH`，写 `java` 很可能报「找不到命令」。

## 6. Nginx 反向代理（可选但推荐）

直接用 8080 对外不优雅，也难加 HTTPS。用 Nginx 转发：

```bash
apt install -y nginx
```

```nginx
server {
    listen 80;
    server_name api.example.com;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

加 HTTPS（有域名时）：

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d api.example.com
```

## 8. 踩坑记录

### ✅ 8.1 MySQL 5.7 触发 Hibernate 警告

启动日志：

```text
WARN ... The 5.7.29 version for [org.hibernate.dialect.MySQLDialect] is no longer supported
```

**原因**：Hibernate 6.6 最低支持 MySQL 8.0。

**处理**：确认只是警告、接口正常，学习继续用 5.7；正式项目升级到 8.0，或者显式指定方言。

**学到的**：`WARN` 和 `ERROR` 要分清。看到红字先判断是「启动失败」还是「只是提示」。

---

### ✅ 8.2 8080 端口被占用

```text
Web server failed to start. Port 8080 was already in use.
```

**原因**：上一次启动的 Java 进程没退出（尤其是我把终端关了但进程还在）。

**处理**：

```powershell
# Windows：找到占用进程
Get-NetTCPConnection -LocalPort 8080 -State Listen
Get-Process -Id <PID>
Stop-Process -Id <PID>

# 或者换端口
$env:SERVER_PORT = "9090"
```

```bash
# Linux
lsof -i :8080
kill -9 <PID>
```

**学到的**：`Ctrl + C` 才是正常退出；直接关窗口可能留下僵尸进程。

---

### ✅ 8.3 PowerShell 里 curl 传 JSON 报 400

```powershell
curl.exe -X POST ... -d "{\"title\":\"测试\"}"
```

后端返回：

```json
{"status":400,"message":"请求体 JSON 格式不正确..."}
```

**原因**：PowerShell 会解析双引号，实际发出去的 JSON 被破坏了。

**处理**：

```powershell
$body = @{ title = "测试"; status = "TODO" } | ConvertTo-Json
$bytes = [System.Text.Encoding]::UTF8.GetBytes($body)
Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/tasks" `
  -ContentType "application/json; charset=utf-8" -Body $bytes
```

**学到的**：PowerShell 的 `curl` 是 `Invoke-WebRequest` 的别名，行为和真正的 curl 不一样。要真 curl 得写 `curl.exe`。

---

### ✅ 8.4 终端里中文显示成乱码，但数据库里是对的

现象：接口返回的 `title` 在控制台显示 `ä¸­æ–‡`，但查数据库 `HEX(title)` 是正确的 UTF-8 字节。

**原因**：终端/管道编码问题，不是数据问题。

**处理**：用 Postman 或浏览器看响应；或在 PowerShell 里 `chcp 65001`。

**学到的**：**先确认数据本身对不对**（`SELECT HEX(col)`），再怀疑显示层。不要一看到乱码就去改数据库字符集。

---

### ✅ 8.5 root 密码不知道，不敢乱动现有数据库

**处理**：不修改现有库，单独建 `task_manager` 库和 `task_app` 专用账号，只授权这个库。

**学到的**：业务永远不要用 root 连数据库；最小权限原则从学习阶段就该养成。

---

### ✅ 8.6 localhost 和 127.0.0.1 不是一回事

Windows 上 `localhost` 可能先解析到 IPv6 的 `::1`，而服务只监听了 IPv4，于是「明明启动了却连不上」。

**处理**：本地调试统一用 `127.0.0.1`；MySQL 建账号时 `'task_app'@'localhost'` 和 `'task_app'@'127.0.0.1'` 是两个不同账号，都建了。

**学到的**：网络问题先分清「服务没起」还是「地址解析不对」。

---

### ✅ 8.7 浏览器工具调本地接口遇到 CORS

用网页版接口工具（如 Apifox Web）访问 `127.0.0.1:8080` 时，浏览器会先发 `OPTIONS` 预检，服务端没返回 CORS 头就报跨域错误。

**处理**：

- 换成 Postman（桌面客户端，不受浏览器同源策略限制）——这是本项目最终采用的方式
- 或者在后端加 CORS 配置（我试过，`WebMvcConfigurer#addCorsMappings` 即可）

**学到的**：CORS 是**浏览器**的限制，不是服务端的 bug。同一个接口，Postman 能通、网页工具不能通，先想到 CORS。

---

### ⚠️ 8.8 服务器常见坑（未实测，提前记录）

| 坑 | 表现 | 预防 |
|---|---|---|
| systemd 找不到 java | `status=203/EXEC` | `ExecStart` 写 java 绝对路径 |
| 内存不足 | 进程被 OOM Kill | `-Xmx512m` 限制堆；2G 机器别开太大 |
| 防火墙没放行 | 本机 curl 通，外网不通 | 云安全组 + `ufw allow 80,443` |
| MySQL 8 认证插件 | `Public Key Retrieval is not allowed` | 连接串加 `allowPublicKeyRetrieval=true` |
| 时区差 8 小时 | 创建时间不对 | 连接串 `serverTimezone=Asia/Shanghai` |
| 中文乱码 | 数据显示 `???` | 库/表/连接三处都 `utf8mb4` |
| Nginx 502 | 网关报错 | 后端没起或端口不对，先 `curl 127.0.0.1:8080` |
| 直接改 jar 里的配置 | 重启就丢 | 用环境变量或外部 `application.yml` |

## 9. 如果让我再部署一次

1. 先只跑 `java -jar`，确认能连库，再写 systemd
2. 密码全部走环境变量，仓库里只留示例

4. 部署完立刻验证「重启后自启」
